# Phase 3a: Tree-sitter Grammar + Editor Syntax Highlighting

## Goal

Create a Tree-sitter grammar for `.zgraph` files providing full syntax highlighting in Neovim (native Tree-sitter) and VS Code (TextMate fallback), with the grammar publishable to npm via bun.

## Scope

**In scope:**
- Tree-sitter grammar definition (`grammar.js`) covering all zgraph syntax
- Highlight queries (`highlights.scm`, `locals.scm`)
- Tree-sitter test corpus
- TextMate grammar (`.tmLanguage.json`) for VS Code — best-effort regex parity
- VS Code extension: language contribution, TextMate grammar, LSP client, language config
- Neovim integration: ftdetect, query files, LSP setup documentation
- Credits section in README

**Out of scope (later phases):**
- WASM compilation of zgraph (Phase 3c)
- Web playground (Phase 3c)
- TUI editor (Phase 3b)
- Document IR / plot blocks (Phase 3d)
- Publishing to VS Code marketplace or nvim-treesitter registry (Phase 4)

## Grammar Definition

### Node Types

The Tree-sitter grammar defines these node types:

| Node type | zgraph construct | Example |
|---|---|---|
| `source_file` | top-level document | entire `.zgraph` file |
| `block` | named block | `graph my_graph { ... }` |
| `block_type` | block keyword | `graph`, `tree`, `table`, `card`, `doc` |
| `block_name` | block identifier | `my_graph` |
| `block_body` | block contents | `{ ... }` |
| `directive` | `@`-prefixed command | `@layout "dagre"` |
| `directive_name` | directive identifier | `layout`, `shape`, `import` |
| `edge_chain` | node connections | `a -> b -> c` |
| `edge_operator` | connection type | `->`, `--`, `<->`, `=>`, `<==>` |
| `identifier` | node/label name | `my_node` |
| `string` | quoted string | `"Hello World"` |
| `property_list` | bracketed properties | `[color=red, shape=box]` |
| `property` | key-value pair | `color=red` |
| `property_key` | property name | `color` |
| `property_value` | property value | `red` |
| `variable_ref` | variable reference | `$name` |
| `table_row` | pipe-delimited row | `\|col1\|col2\|` |
| `table_cell` | cell content | `col1` |
| `comment` | line comment | `// this is a comment` |
| `number` | numeric literal | `42`, `3.14` |

### Grammar Rules (grammar.js)

```javascript
module.exports = grammar({
  name: 'zgraph',

  extras: $ => [/\s/, $.comment],

  rules: {
    source_file: $ => repeat($._statement),

    _statement: $ => choice(
      $.block,
      $.directive,
      $.edge_chain,
      $.variable_def,
    ),

    block: $ => seq(
      field('type', $.block_type),
      field('name', optional($.block_name)),
      '{',
      field('body', optional($.block_body)),
      '}',
    ),

    block_type: _ => choice('graph', 'tree', 'table', 'card', 'doc'),

    block_name: $ => choice($.identifier, $.string),

    block_body: $ => repeat1($._block_statement),

    _block_statement: $ => choice(
      $.edge_chain,
      $.directive,
      $.table_row,
      $.card_field,
      $.block,        // nested blocks
    ),

    directive: $ => seq(
      '@',
      field('name', $.directive_name),
      optional(field('value', choice($.string, $.identifier, $.number, $.property_list))),
    ),

    directive_name: _ => /[a-zA-Z_][a-zA-Z0-9_]*/,

    edge_chain: $ => seq(
      $._node_ref,
      repeat1(seq(
        $.edge_operator,
        $._node_ref,
      )),
    ),

    _node_ref: $ => seq(
      choice($.identifier, $.string),
      optional($.property_list),
    ),

    edge_operator: _ => choice('->', '--', '<->', '=>', '<==>'),

    property_list: $ => seq(
      '[',
      $.property,
      repeat(seq(',', $.property)),
      ']',
    ),

    property: $ => seq(
      field('key', $.property_key),
      '=',
      field('value', $.property_value),
    ),

    property_key: _ => /[a-zA-Z_][a-zA-Z0-9_]*/,

    property_value: $ => choice($.string, $.identifier, $.number, $.variable_ref),

    variable_def: $ => seq(
      $.variable_ref,
      '=',
      choice($.string, $.identifier, $.number),
    ),

    variable_ref: _ => /\$[a-zA-Z_][a-zA-Z0-9_]*/,

    table_row: $ => seq(
      '|',
      repeat1(seq($.table_cell, '|')),
    ),

    table_cell: _ => /[^|\r\n]+/,

    card_field: $ => seq(
      field('key', $.identifier),
      ':',
      field('value', choice($.string, $.identifier, $.number, $.variable_ref)),
    ),

    identifier: _ => /[a-zA-Z_][a-zA-Z0-9_]*/,

    string: _ => /"[^"]*"/,

    number: _ => /\d+(\.\d+)?/,

    comment: _ => token(seq('//', /.*/)),
  },
});
```

**Note:** This is the design-level grammar. The implementation may need adjustments for ambiguity resolution (e.g., `prec()` calls, `conflicts` array) discovered during `tree-sitter generate`.

## Highlight Queries

### highlights.scm

```scheme
; Keywords
(block_type) @keyword

; Block names
(block (block_name (identifier) @function))
(block (block_name (string) @function))

; Directives
(directive "@" @attribute)
(directive_name) @attribute

; Operators
(edge_operator) @operator

; Strings
(string) @string

; Numbers
(number) @number

; Comments
(comment) @comment

; Properties
(property_key) @property
(property_value (string) @string)
(property_value (identifier) @string)
(property_value (number) @number)

; Variables
(variable_ref) @constant
(variable_def (variable_ref) @constant)

; Table
(table_row "|" @punctuation.delimiter)
(table_cell) @string

; Card fields
(card_field (identifier) @property)

; Punctuation
"{" @punctuation.bracket
"}" @punctuation.bracket
"[" @punctuation.bracket
"]" @punctuation.bracket
"," @punctuation.delimiter
"=" @operator

; Identifiers (nodes in edge chains)
(edge_chain (identifier) @variable)
```

### locals.scm

```scheme
; Blocks create scopes
(block) @scope

; Variable definitions
(variable_def (variable_ref) @definition.var)

; Variable references
(property_value (variable_ref) @reference)
```

## TextMate Grammar

The `zgraph.tmLanguage.json` covers:

| Scope | Pattern |
|---|---|
| `keyword.control.zgraph` | `\b(graph\|tree\|table\|card\|doc)\b` |
| `entity.other.attribute-name.zgraph` | `@[a-zA-Z_]\w*` |
| `keyword.operator.zgraph` | `<==>\|<=>\|<->\|=>\|->` (longest first) |
| `string.quoted.double.zgraph` | `"[^"]*"` |
| `comment.line.double-slash.zgraph` | `//.*$` |
| `constant.other.variable.zgraph` | `\$[a-zA-Z_]\w*` |
| `constant.numeric.zgraph` | `\d+(\.\d+)?` |
| `punctuation.separator.table.zgraph` | `\|` (inside table context) |
| `entity.name.function.zgraph` | identifier after block_type keyword |
| `support.other.property.zgraph` | identifier before `=` inside `[...]` |
| `punctuation.bracket.zgraph` | `[{}[\]]` |

Block scoping uses `begin`/`end` patterns on `{`/`}` to enable nested highlighting.

## VS Code Extension

### package.json

Key contributions:
- `languages`: `.zgraph` file association, language ID `zgraph`
- `grammars`: TextMate grammar reference
- `configuration`: language configuration reference

### language-configuration.json

- Comment toggling: `//`
- Bracket pairs: `{}`, `[]`
- Auto-closing pairs: `{}`, `[]`, `""`
- Folding markers: `{`/`}`

### LSP Client (extension.ts)

- On activation, spawn `zgraph lsp` as the language server
- Connect via stdio transport
- Register for `.zgraph` document selector
- Configuration: path to `zgraph` binary (falls back to `zgraph` on PATH)

### Build

- TypeScript compiled with esbuild
- Packaged with `@vscode/vsce`

## Testing Strategy

### Tree-sitter Test Corpus

Each `.txt` file in `test/corpus/` uses Tree-sitter's test format:

```
================
Test name
================

source code here

---

(expected_tree)
```

Test files:
- `blocks.txt`: all block types, nested blocks, named/unnamed blocks
- `edges.txt`: all operator types, chains, properties on nodes
- `directives.txt`: all directive types with various value forms
- `tables.txt`: table rows, multi-column, empty cells
- `comments.txt`: standalone comments, inline comments, comments in blocks

### TextMate Grammar Testing

- Manual verification with VS Code's "Inspect Editor Tokens and Scopes" command
- Sample `.zgraph` files in `editors/vscode/test/` for visual inspection

### VS Code Extension Testing

- Extension loads without errors
- `.zgraph` files get correct language ID
- LSP client connects to `zgraph lsp` process
- Formatting request works end-to-end
